# 사주궁 확정 디자인 — B안

사용자가 승인한 화면 기준은 최종 B안입니다. A안과 예전 보라색 모바일 카드 홈은 기준이 아닙니다. “기본 뼈대 유지”는 현재 서비스·회원·결제·계산·저장 구조를 보존한다는 뜻이며, 화면은 이 B안으로 구현합니다.

## 실제 앱의 기준 파일

| 화면 | 적용 파일 |
|---|---|
| 홈 진입 | `app/page.tsx` → `app/components/home/SampleHome.tsx` |
| 홈 배치·반응형 | `app/components/home/home.css` → `conversion.css` → `refinement.css` → `trust.css` |
| 색상·한글 서체 | `app/globals.css`, `app/layout.tsx`, `public/fonts/` |
| 결과 공통 화면 | `app/components/reading/ReadingResult.tsx` |
| 결과 스타일 적용 순서 | `results.css` → `approved-b.css` (최종 수정값) |
| 실제 결과 연결 | `app/saju/page.tsx`, `app/daily/page.tsx`, `app/result/[shareId]/page.tsx` |
| 공개 가상 결과 예시 | `app/examples/saju/page.tsx` |
| 실제 후기 | `app/components/reviews/ReviewsPreview.tsx`, `ReviewCard.tsx`, `reviews.css`, `app/reviews/page.tsx` |
| 1:1 대화 진입 | `app/components/conversation/ConversationBanner.tsx`, `/chat`, `/consultation` |

실행 명령은 기존 Next.js의 `npm run dev`, `npm run build`, `npm start`입니다. Vite preview 실행이나 정적인 홈 페이지 교체로 운영 앱 적용을 대신하지 않습니다. 디자인 선택용 A/B 스위치는 실제 앱에 두지 않습니다.

## B안 수치와 배치

아래는 기본 16px 글꼴·100% 배율에서의 CSS 기준입니다. 문구와 사용자 입력 길이에 따라 자연스럽게 높이가 늘어납니다.

| 항목 | 확정 기준 |
|---|---|
| 홈 바탕 | `#141a24` |
| 인물 배너 바탕 | `#202735` |
| 주요 글자 / 보조 글자 / 구분선 | `#f2f1ed` / `#a7afb9` / `#343b47` |
| 홈 포인트 / 주 버튼 | `#c9ac86` / 밝은 아이보리 `#eeeae3`, 버튼 글자 `#19212e` |
| 서체 | 원본 PalaceSans·PalaceSerif 파일 사용. B안 홈 큰 제목은 PalaceSans |
| 홈 최대 폭 | 1,120px, 데스크톱 좌우 패딩 32px |
| 큰 배너 | 데스크톱 본문 최소 높이 510px, 제목 64px·행간 1.28, 인물 오른쪽 폭 54% |
| 모바일 배너 | 767px 이하 본문 최소 높이 480px, 제목 36px. 359px 이하 패딩·글 영역 별도 조정 |
| 자동 전환 | 4명·6초 간격·부드러운 전환. 이전/다음/일시정지 제공. 읽는 동안·비활성 탭·동작 줄이기 설정 대응 |
| 안내자 카드 | 데스크톱 4열, 모바일 2열. 원본 인물 사진·자르기·하단 명암·텍스트 위치 유지 |
| 홈 후기 | ‘후기 게시판’ 제목, 실제 최신 2개, 전체 후기 링크. 게시판은 기존 페이지네이션 유지 |
| 하단 메뉴 | 홈·사주·1:1 대화·일일운세·보관함·신령 6개 |
| 결과 최대 폭 | 바깥 740px, 본문 720px 범위 |
| 결과 표지 | 높이 자동·최소 205px, 제목 28px·행간 1.4. 긴 이름과 내용 때문에 잘리지 않게 높이 증가 |
| 결과 사진 | 데스크톱 폭 40%, 540px 이하 45%. Next Image fill의 기본 폭은 지정 비율로 보정 |
| 결과 본문 | 17px·행간 1.9. 글자 크게 20px |
| 만세력 | 시주·일주·월주·연주 4열 고정, 각 칸 최소 140px. 모르는 시각은 시간 미입력 |
| 결과 순서 | 기본 해석 12개 → 인생 흐름·전략 → 선택 질문. 서버가 허용한 실제 내용만 표시 |
| 좁은 화면 | 320/360/390/430px에서 가로 넘침·잘린 버튼·겹침 없이 세로로 읽기 |

섹션 순서: 상단 로고·후기·로그인/잔액 → 큰 인물 배너 → 저장 결과 진입(로그인 시) → 결과 구성 안내 → 무료 운세 → 움직이는 1:1 대화 배너 → 후기 → 4명 안내자 → 운세 메뉴·이용 조건 → 결과 미리보기 → 풀이 방식·FAQ → 첫 이용 안내 → 충전·푸터.

## 시안과 실제 서비스의 데이터 차이

그림·배치·색상·서체는 위 기준으로 맞춥니다. 샘플 고객 후기, 가짜 로그인, 가짜 결제 성공, 예시 AI 응답은 운영 서비스의 데이터로 사용하지 않습니다. 실제 후기가 없으면 같은 디자인의 빈 상태가 보입니다. 예시 화면은 가상 결과라는 표시가 있어야 합니다.

미권한 결과의 샘플 1개 제한, 서버 소유권, 무료 이용권 기준, 구매·환불 원장, 문의·공유 권한은 그대로 유지합니다. 궁합·대운·택일·연도별 신규 생성이 준비 중인 상태를 화면 일치를 위해 임의로 해제하지 않습니다. 기존 사업자·가격 정책을 경쟁사 기준으로 바꾸지 않습니다.

## 완료 판정

1. `B_FILES.json`의 파일 경로와 해시로 적용된 소스를 확인합니다. 해시 불일치는 변경 여부를 보여주는 근거이며 보안 서명은 아닙니다.
2. 새 소스로 Next 프로덕션 빌드·타입·린트 검사를 통과합니다. 현재 브랜치의 HTML에 `direction direction-b`와 결과 컴포넌트가 실제로 연결되어야 합니다.
3. 브라우저 접근이 허용된 환경에서 320/360/390/430/768/1440px, 배율100%, 글꼴·이미지 로드 완료 후 확인합니다. 캐러셀은 같은 인물에서 일시정지한 상태로 비교합니다.
4. 홈 전체, 실제/가상 결과, 후기, 상담 진입을 촬영하고 B안과 나란히 비교합니다. 로그인/후기 유무·데이터 길이 차이와 디자인 차이를 분리해 기록합니다.
5. 자동 전환·일시정지·목차·글자 확대·세로 스크롤·키보드 포커스·충전창을 실제 조작합니다. 홈 방문 전후에도 결과 스타일이 같아야 합니다.
6. GitHub 반영 커밋과 Vercel 배포 커밋을 확인합니다. 로컬 수정이나 ZIP 전달만으로 기존 사이트 주소가 바뀐다고 보고하지 않습니다.

현재 여기에서 확인한 것은 소스·빌드 수준입니다. 브라우저 권한이 거부되어 픽셀 비교·실기기 조작은 실행하지 않았습니다. 이후 실행자도 접근이 거부되면 다른 방법으로 우회하지 말고 미검증으로 보고합니다.

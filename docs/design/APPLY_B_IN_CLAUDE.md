# Claude Code 실행 지시문 — 사주궁 B안 그대로 적용

아래 지시문을 이 ZIP과 함께 전달하세요. ZIP 안 `sajuya-upgraded/`가 실행 소스입니다.

---

사주궁을 첨부한 최종 B안과 같은 디자인으로 실제 Next.js 앱에 적용해줘. 기획 제안으로 끝내지 말고, 파일 수정·연결·빌드·검수까지 진행해줘.

## 1. 기준 확정

- 이 ZIP의 `sajuya-upgraded/docs/design/B_DESIGN.md`를 먼저 읽어. 색상·배치·글꼴·사진 크기·섹션 순서와 반응형 기준을 임의로 재해석하지 마.
- `docs/design/B_FILES.json`에는 기준 화면 파일의 SHA-256이 있어. 첨부 소스가 무엇인지 확인하고 현재 저장소와 비교해.
- 기본 뼈대를 지키라는 말은 사주궁의 회원·로그인·사주 계산·결제·환불·저장 구조를 살리라는 뜻이야. 예전 보라색 홈 화면을 유지하라는 뜻이 아니야.
- 현재 GitHub 코드를 기준으로 이미 더 최신 기능 수정이 있다면 보존하고, 이 ZIP의 B안 화면을 그 위에 연결해. 무조건 전체 덮어쓰기는 하지 마.
- 별도 Vite 시안만 실행하거나 새로운 예시 홈페이지를 만드는 것으로 완료 처리하지 마. 실제 `app/page.tsx`와 실제 결과 경로가 바뀌어야 해.

## 2. 실제 작업 환경 확인

현재 경로, Git 브랜치·HEAD·작업 중인 변경, 연결된 원격 저장소, 읽기·쓰기 권한을 먼저 확인해. 키나 토큰의 값을 출력하지 마. 사용자 변경은 보존하고 별도 작업 브랜치에서 진행해. 파일 비교·로컬 수정·테스트는 가능한 범위까지 바로 실행해. 접근이 차단되면 우회하지 말고 어느 작업이 미완료인지 정확히 알려줘.

## 3. 적용할 화면

- 홈은 `app/components/home/SampleHome.tsx`의 고정 B안. 큰 인물 사진·제목, 자동 전환, 무료 운세, 움직이는 1:1 배너, 후기, 4명 안내자, 운세 메뉴, 결과 예시, FAQ, 하단 메뉴 순서를 유지해.
- B안 CSS와 `public/fonts/`를 같이 적용해. CSS 이름만 바꾸거나 색상만 비슷하게 만드는 것으로 끝내지 마.
- 결과는 `app/components/reading/ReadingResult.tsx`를 사용해. `results.css` 다음에 `approved-b.css`가 적용되어야 해. 최종 글자 크기·행간·표지 높이·모바일 값이 이 파일에 있어.
- 실제 사주 생성 결과 `/saju`, 일일운세 `/daily`, 저장 결과 `/result/[shareId]` 모두 공통 결과 화면에 연결해.
- `/examples/saju`는 로그인 없이 보는 가상 결과 예시야. 실제 개인 결과의 공개·결제 권한과 혼동하지 마.
- 후기·보관함·로그인·충전·상담 화면도 첨부된 디자인 기준을 사용해. 1:1 직접 대화는 `/chat`, 선택형 상담은 `/consultation`이야. 하나를 빠뜨리지 마.

## 4. 실제 기능 보존

- 미권한 결과는 서버에서 샘플 1개만 보내도록 유지해. 화면에서만 가리는 방식으로 바꾸지 마.
- 실제 로그인·결제 확인·잔액·환불·재시도·원장 처리를 샘플 코드로 바꾸지 마.
- 후기는 실제 DB의 데이터를 표시해. 최신 2개는 홈에, 나머지는 게시판에 표시해. 회원당 1개·400자·수정/삭제·갱신·작성 자격은 유지해.
- 화면을 채우기 위해 가짜 후기·가짜 회원 수·가짜 AI 답변을 넣지 마.
- 준비 중 상품을 화면 일치를 위해 판매 가능으로 바꾸지 마. 무료 횟수·상담 가격·토큰 제한도 임의로 바꾸지 마.

## 5. 검증

1. 저장소에 선언된 의존성·잠금 파일을 기준으로 설치하고 `npm run build`, `npm run typecheck`, `npm run lint`를 실행해. 의존성 업데이트는 별도 이유 없이 하지 마.
2. 적용 과정에서 서버 기능을 건드렸다면 관련 테스트를 실행해. 권한·결제 관련 파일을 변경했다면 기존 `test:security`, `test:refunds`, `test:http` 검증을 생략하지 마.
3. 로컬 또는 승인된 검수 배포를 실제 브라우저에서 열어. 브라우저 접근이 허용된 환경에서만 진행해.
4. 320/360/390/430/768/1440px, 배율 100%, 글꼴·이미지가 로드된 상태에서 확인해. 같은 인물 배너로 멈춘 뒤 홈 전체·결과·후기·상담 화면을 확인해.
5. 가로 넘침, 글자 잘림, 사진 자르기, 버튼 겹침, 하단 메뉴가 마지막 내용을 가리는 현상을 점검해. 로그인 상태·미로그인 상태와 후기가 없는 상태도 확인해.
6. 자동 전환·일시정지·키보드 포커스·목차 이동·글자 확대·세로 스크롤·상담 진입·충전창을 실제 조작해.
7. 홈 → 결과 → 홈으로 이동해도 글자 크기와 배치가 바뀌지 않는지 확인해. 이전 화면 CSS가 다음 화면을 덮으면 범위를 고쳐.
8. 문제가 있으면 고친 파일과 그 문제가 생기는 조건을 다시 확인해. 검사하지 못한 항목은 통과로 쓰지 마.

## 6. 반영과 보고

기존 세션에서 승인된 GitHub·배포 범위에 따라 진행해. 운영 배포 승인이 아직 없다면 수정본·검수 화면·검사 결과를 먼저 준비해서 마지막에 승인받아. 반영 권한이 없으면 실제 수정 파일과 패치를 전달하고, push·배포는 미완료로 구분해.

GitHub에 올렸다면 실제 커밋과 변경 파일을 알려줘. 배포했다면 Vercel이 어떤 커밋을 빌드했는지 확인해. 프로젝트·브랜치·Root Directory가 맞는지도 확인해. 로컬에서만 고치고 사이트도 바뀌었다고 하지 마.

최종 보고에는 다음만 명확히 적어줘.

- B안과 맞춘 화면·파일
- 남아 있는 시각적 차이와 이유
- 실제 실행한 검사와 결과
- 실제 브라우저 화면 캡처 또는 미검증 사유
- GitHub 반영 여부와 커밋
- 배포 여부·검수 주소·배포 커밋
- 내가 마지막으로 확인할 부분

이전 답변에서 통과했다고 한 검사나 점수를 이번 실행의 증거로 대신하지 마. 직접 확인한 범위만 보고해.
